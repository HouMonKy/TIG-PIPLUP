# E2：结构感知分词与字符级日志头边界识别实验报告

**项目：** TIG-2026 / PIPLUP HeaderDetector V1.1  
**分支：** `exp/header-v11-span`（自 E0 基线提交 `8fb2c985` 创建，与 E1 相互独立）  
**日期：** 2026-10-21

---

## 0. 结论摘要

1. **Span-aware 分词全面达成实验目标**：在独立括号挑战集上
   Boundary Accuracy **0.693 → 0.868**（+17.5pp），Over-strip
   **0.304 → 0.051**（−83%）；在 22 个原有数据集上宏平均
   **0.732 → 0.803**（+7.1pp），Over-strip 反而下降（0.0573 → 0.0503）。
   非括号为主的 Loghub 干净格式保持持平（0.821 → 0.821，−0.2pp）。
2. **四类此前不可解的失败模式被修复**：多 token 括号字段
   （Hadoop `[IPC Server handler 4 on 62270]`）、跨 token 内容括号
   （Messages `[t][i][i][l][content]...` 0 → 0.926）、未闭合括号
   （挑战集 cat3 0 → 1.000，Over 0.968 → 0）、附着正文
   （`[svc]disk 15448...` 字符级精化）。
3. **E2-D 前缀限定分析与完整分析质量相当**（宏平均 0.8043 vs 0.8029，
   p95 延迟更低），按计划原则采纳前缀限定方案。
4. **推理开销**：span 分词 + 守卫 + 精化使单行预测耗时
   18.2µs → 26.3µs（×1.44），p95 33.5µs → 46.1µs，
   吞吐 54.6k → 37.9k lines/s。**建议 span 分析保留在离线规则学习阶段**
   （E4 方向 B），在线走编译后的字符偏移规则，与本实验结论一致。
5. **重要副产物（基线修正）**：复用 E0 M3 时发现两处实现缺陷
   （value-split 节点未按值遍历、未闭合括号无安全检查），修复后
   空白分词 M3 在 E0 原协议下 all22 从 0.663 升至 0.733。
   E2-A 采用修复版 M3 作为对照，偏移已在 §1.3 声明。
6. **建议 E2-C/E2-D 进入 E5 组合实验**（条件见 §7）。

## 1. 实验设计

### 1.1 方法组

| 方案 | 实现 |
|---|---|
| E2-A | E0 的 M3（空白分词），仅作对照。含两处 bugfix（§1.3） |
| E2-B | M3 算法不变，分词换为 `SpanAwareTokenizer`（无守卫/精化） |
| E2-C | E2-B + 括号内容守卫 + 内型分裂 + 字符级边界精化 + 连续强前缀 Guard-B 回退 |
| E2-D | E2-C + 前缀限定扫描（最多 17 个 span / 256 字符） |

所有方法共用同一 M3 扫描内核（分词器注入式重构，见
`bench/header_detector/methods.py`）；E2-B/C/D 的差异全部通过
覆写钩子实现（`span_methods.py`），保证消融可归因。

### 1.2 SpanAwareTokenizer（`spantok.py`）

- Span = 括号深度 0 处的最长非空白字符运行，**保证
  `raw[start:end] == text`**（半开区间），不增删改任何字符。
- 含空格的括号字段保持完整：`[2026-10-13 10:00:01]`、
  `[AsyncDispatcher event handler]`、`[req-x - - -]` 均为单 Span。
- **最小相邻分裂规则**：仅当 Span 以括号组开头且该组闭合后紧跟另一个
  开括号时分裂（`[time][level][proc]` → 3 个 Span）；
  前缀/后缀附着不分裂（`sshd(pam_unix)[19939]:`、`kernel[0]:`、
  `workerEnv.init()`、`05:29:14.000000[INFO][svc]disk` 各为单 Span，
  附着文本由字符级精化处理）。
- **安全回退**：行尾括号不平衡时该 token 退回纯空白分词
  （`[scheduler pending` → `[scheduler` + `pending`）；
  `< >` 不视为括号（比较运算/泛型歧义）。
- **结构锚点**：每个 Span 记录 `last_close_end`（最后一个在深度 0
  闭合的括号组之后的位置），供边界精化使用。

### 1.3 E2-A 基线声明（重要）

E2 复用 E0 M3 时发现两处实现缺陷并修复（修复属于 E2 分支，
E0 分支与已发布报告不动）：

1. **by_value 遍历缺陷**：M3 的未闭合括号值分裂节点构造时未传
   `by_value=True`，预测遍历永远 miss → 全部保守保留。E0 已发布的
   M3 数值被该缺陷压低。
2. **未闭合括号安全检查**（`_bracket_closes_later`）：永不闭合的
   `[` 不再被当作头部字段消费（挑战集 cat3 的直接动机）。

修复后的空白 M3 在 **E0 原协议**（500/rest 划分）下的偏移：

| 指标 | E0 已发布 | 修复后 |
|---|---:|---:|
| Loghub acc | 0.7616 | 0.8203 |
| 压力集 acc | 0.4900 | 0.5813 |
| all22 acc | 0.6628 | **0.7334** |
| all22 over | 0.0374 | 0.0449 |

逐数据集显著变化：OpenStack 0.043→0.801、bracket-space 0.384→0.986、
Hadoop 0.750→0.815、oam-console 0.330→0.459。
**E2-A = 修复版 M3**（更诚实 的对照）；E1 的 M3-raw 参照系使用的是
未修复版，其内部对比仍然自洽，但跨实验引用 M3 绝对值时以本表为准。

### 1.4 E2-C 的三个新机制

1. **括号内容守卫**（`_bracket_position_is_body` + `inner_kind`）：
   括号包裹 ≠ 头部。内型为"自由文本"（≥2 词、≥60% 纯词、无时间模式）
   且值多样性 >0.5 的括号位置判为正文（实验计划 E2 要求 6 的实现）。
2. **内型分裂**（`_bracket_kind_partition`）：同一签名下混合了
   内容括号与结构括号时（Messages 的不同 id 数量格式），按内型分裂：
   content 侧停、structural 侧在前瞻 3 位内仍有括号结构时才继续
   （`[user5639] opened session` 的 user 括号后无结构 → 停）。
3. **字符级边界精化**（`predict_offset`）：边界 Span 若含已闭合括号组
   且其后紧跟词字符（`[osd-daemon]connection`、`[dme-server]disk`），
   `body_start = last_close_end`——正文由 `raw[offset:]` 直接切片得到，
   不经 token 重组。输出：
   `{"body_start_offset": N, "method": "span_aware", "confidence": null,
     "span_boundary": b, "refined": bool}`（confidence 留待 E3 规则级校准）。

另有 span 专用 **Guard-B 回退**：模板化正文被整体吞掉时，切到
**从位置 0 起的连续强类型前缀**之后（正文中的孤立括号不算证据，
保护 `status [ok 77] ...` 类无头部行）。

### 1.5 数据与协议

- 22 个原数据集 + **独立挑战集**（种子 4242，词表与调参样本完全
  独立，8 类 × 200 行，`gen_challenge.py`）：
  正常 / 多空格 / 嵌套 / 未闭合 / 正文含括号与附着正文 / 无头部 /
  混合格式 / 头部-正文相似结构。
- 统一划分（种子 42）：learn 30% / val 20% / test 50%（val 本实验
  未用于选择，保留给后续实验复用同一划分）。守卫阈值
  （word_frac 0.6 / distinct 0.5 / 前瞻 3）为**先验固定值**，未在
  挑战集上调参。
- 评估：字符级四分类 + 计划 §9.1 全部指标；性能为 pooled test
  逐行计时（5 次取中位）。

## 6. 未解决的失败案例（明确原因，不堆叠启发式）

| 失败模式 | 案例 | 量化 | 原因 |
|---|---|---|---|
| 值样正文首词 | `[svc] vm-61e8 reported...`（host-body） | over 0.448–0.510（各方法一致） | `vm-61e8`(ID) 与头部 id 字段在位置统计上不可区分——**E3 置信度门控的目标**，span 层无解 |
| 常量 IP 正文首词 | OpenStack `... [req-...] 10.11.10.1 "GET ...` | over 0.280（A 为 0.204） | 客户端 IP 跨行恒定，与头部 host 字段同构；span 版把 req 括号合并后位置统计更强反而多剥 1 个 IP——本质同上，转 E3 |
| 冒号尾正文首词 | `backpressure: inbound queue at 92 percent`（挑战 cat0/1/2 over ~0.1） | over ≈0.09–0.11 | `word:`(CTAIL) 与头部 `component:` 同构；转 E3 |
| Mac 方法名前缀 | `-[UABestAppSuggestionManager notifyBe...]` | Mac 0.778 | 正文以 `-[Obj method]` 开头，括号结构+驼峰与头部字段同构 |
| Hadoop 守卫代价 | E2-B 0.998 → E2-C 0.920 | −8pp | 少数线程名内型被误判 content 或分裂提前停止；换取 Messages/挑战集大幅收益，净值显著为正 |
| 管道/单 token | HealthApp `a|b|c|body` | 0.000 | 无括号结构，span 分词无助于无分隔符格式 |
| HPC 异构节点字段 | `node-246` vs `Interconnect-0N03` vs `full` | 0.229（各方法一致） | E0 已知 C6 类，与分词无关 |

## 7. 性能开销

| 方案 | avg µs/行 | p50 | p95 | lines/s | fit 合计 s |
|---|---:|---:|---:|---:|---:|
| E2-A（空白 M3） | 18.22 | 16.58 | 33.46 | 54,606 | 0.81 |
| E2-B | 26.03 | 24.21 | 45.92 | 38,268 | 0.93 |
| E2-C | 26.27 | 24.54 | 46.08 | 37,923 | 1.18 |
| E2-D（前缀） | 26.11 | 25.04 | **42.96** | 38,150 | 1.17 |

- 单行开销 ×1.44（+8µs），p95 ×1.38；守卫/精化本身仅 +0.2µs
  （E2-C vs E2-B）——**成本几乎全在 span 扫描**，守卫是廉价的。
- E2-D 在 pooled 短行上吞吐与 E2-C 相当、p95 略优；对超长行
  （>256 字符）收益更大。峰值 RSS：整个 E2 运行（全部数据集驻留 +
  4 个方法）≈44MB（macOS ru_maxrss），方法间无实质差异。
- **结论与计划 §8 预期一致**：span 分析 + 守卫 + 分裂的学习成本
  应留在**离线规则学习阶段**；在线由 E4 把学到的
  （签名, span 边界, 字符偏移, 置信度）编译为确定性规则。
  本表为 span 机制本身的代价测量，不替代 E4。

## 8. 是否建议进入 E5 组合实验

**建议：E2-C/E2-D 进入 E5**，理由与条件：

1. 挑战集与压力集的大幅收益（+17.5pp / +18.6pp）且 over-strip
   不升反降，满足验收原则 1–3；
2. E2-D 与 E2-C 质量等价、p95 更低，**采纳 E2-D 作为代表**；
3. 字符级输出接口（`body_start_offset` 直接切片）满足计划 §6.2；
4. **组合时的注意**：(a) E2 改变边界表示（span 级 + 字符偏移），
   E1 的规则学习需在 span 签名上重建（E1 的 (source, signature)
   框架直接适用，签名 = span 族类型）；(b) E3 的置信度校准必须
   在 span 规则上重新进行，不可复用 token 级阈值；(c) E1 报告中的
   M3-raw 参照值为未修复 M3，跨实验引用以本报告 §1.3 修正表为准。
5. 遗留失败模式（值样正文首词、常量 IP、CTAIL 正文）全部归类为
   **E3 门控问题**，本实验不再追加启发式。

## 9. 复现方式

```bash
git worktree add -b exp/header-v11-span ../header-v11-span 8fb2c985
python3 -m bench.header_detector.gen_challenge   # 挑战集（种子 4242）
python3 bench/header_span.py                     # 全部质量+性能实验
python3 bench/header_ablation.py                 # E2-A 基线偏移验证（§1.3）
```

配置：种子 42（划分）/ 4242（挑战集）；learn/val/test = 30/20/50；
守卫 word_frac 0.6、distinct_ratio 0.5、前瞻 3 位；前缀限制
17 span / 256 字符；性能 5 次取中位。环境：Python 3.13.5，纯标准库。
