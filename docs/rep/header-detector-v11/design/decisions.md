# 关键设计决策及其证据

每条决策标注：**证据**（实验数据） / **权衡**（被放弃的替代方案）。
未标注"已验证"的部署建议均为推断。

---

## D1. 重建基线而非伪造复现（E0）

- **证据**：历史 V1（`ac30623d`/`final`/`bench/header_ablation.py`）
  在仓库及两个远端全面检索确认缺失；重建 M1–M4 的定性模式与历史
  一致（M1 不可用 / M2 标准格式强 / M3 复杂强 / M4 劣于 M3），
  数值不宣称可比（报告 §0.3 声明）。
- **权衡**：不做任何"凑近历史数字"的调参。

## D2. 规则按 (source, signature) 二级键控（E1）

- **证据**：合并学习实验中 Linux/OpenSSH 共享 syslog 签名互相污染
  （主机值不同→边界错位），per-source 后修复。
- **权衡**：纯签名全局规则——被证伪；来源=生产可得元数据，不算
  按数据集名硬编码（方法选择仍由结构族 val 表现决定）。

## D3. 签名仅分组，组内扫描从位置 0 重启（E2）

- **证据**：4-token 签名若同时作为边界下限，3-token 头格式
  （noheader/host-body）必然过剥 1 token；重启后 noheader 1.000。

## D4. 最小相邻括号分裂 + 字符级精化（E2）

- **证据**：激进分裂（plain→bracket 也分）破坏组件字段
  （`sshd(pam_unix)[19939]:` → 弱词停止，Linux/Mac/Apache 崩溃）；
  最小分裂（仅跨开头纯括号组）+ `last_close_end` 精化后，
  附着正文（`[svc]disk`）与括号链（`[t][i][l][content]`）同时可解。
- **权衡**：Messages 全括号行依赖相邻分裂 + 内容守卫联合工作。

## D5. 括号内容守卫 + 内型分裂 + 前瞻约束（E2）

- **证据**：守卫修复 Messages 0→0.926、挑战集 cat7 0.387→0.972；
  无前瞻约束时 cat7 user 括号被结构性续扫（over 回升 0.557）；
  前瞻 3 位使 `[user5639] opened`（后无结构）停、
  `[t][i][i][l][content]`（后有括号）续。
- **权衡**：Hadoop 守卫代价 −8pp（E2-B 0.998→E2-C 0.920），
  换 Messages/挑战集大幅收益，净值显著为正。

## D6. 门控规则键 = (签名, 边界结构组合)（E3）

- **证据**：OpenStack 同族正确路径（value_start=True 组合）与误删
  路径（吞 `[instance: uuid]`，全 False 组合）可分；组合并入键后
  over 4.29%→0.45%（拦截 89.6%）而覆盖保留 81%。
  值样结尾组合 val over 14.1% 为最强风险信号。
- **权衡**：族级全有全无门控（E3-B 初版）correct-loss 20.8% →
  组合键细化后 11.75%（93% 集中在 4 个 val 高危族）。

## D7. E3-C 独立正文风险层不保留（E3，负面结果）

- **证据**：在组合键控 B 之上零增量（D≡B，拦截率 0 增）；
  单独使用拦截率仅 34%（兜底组合 (F,F,F,F) 含 4.8% val over，
  全局先验无法安全拦截族级病灶）。
- **结论**：风险信号的价值已被规则键吸收，不作为独立层进 E5。

## D8. 双工作点 τ_B∈{0.4, 0.2}（E3→E4）

- **证据**：val 选定；τ=0.4 over 0.45%/覆盖 0.714，
  τ=0.2 over 0.91%/覆盖 0.771；两者仅门控放行位不同（树相同），
  E4 性能无差异，工作点选择移交业务风险偏好。

## D9. 在线零模型零统计（E4）

- **证据**：18,798 行双 τ 逐行等价（P1/P2/P3 与 E3-B 四维全同）；
  在线路径排除项合规自查（无 PositionStats/分裂学习/边界搜索/
  跨行置信度/全规则遍历/整行扫描）。
- **权衡**：P1 顺序扫描随规则数退化（114 条规则 31.2µs），
  被 P2/P3 两级索引取代（来源 23→736 扩展平坦）。

## D10. 未知来源默认 KEEP；来源名是安全边界（E1/E3/E4 一致）

- **证据**：E1 LODO 签名迁移在压力格式间 over 12.8%（dsware）；
  E3 LODO 全局风险表压 over 但覆盖崩塌；E4 来源索引天然隔离
  （LODO 0 违例），但跨源误路由的精确结构碰撞可剥离
  （误配场景 dsware 570 行 over）——正确路由下 dsware over=0。
- **结论**：生产要求来源标识可信；不做模糊迁移。

## D11. `by_value` 缺陷修复随 E2 基线修正发布（E2）

- **证据**：E0 发布的 M3 数值被压低（all22 0.663→修复后 0.733，
  OpenStack 0.043→0.801）；E1-A/B/C 在修复版下逐位不变
  （自适应选择的保守性对基线修复免疫，E3 前置检查验证）；
  E2 之后所有实验使用修复版并以报告 §1.3 声明偏移。

## D12. 挑战集 GT 前导空格怪癖（E3 发现，未修正）

- **证据**：39 行挑战集 over 为仅删除 1 个空白字符（正文模板
  ` evicted...` 前导空格），零内容损失；已从指标上分离
  （content_over_rate）。
- **决定**：不改已提交 GT（保持 E2/E3 结果可比）；E5 前可修正
  生成器（影响 39 行统计，不影响方法结论）。
