# 整体架构：离线学习 + 在线规则匹配

**来源：** E0–E4 实验验证的架构（E4 报告 §1–§2 为最终形态）  
**分级：** 本文档描述的流水线形态已被 E4 逐行等价性验证；标注【推断】的
部署细节未经生产验证。

```
┌───────────────────────────── 离线（每个来源/模块一次） ─────────────────────────────┐
│                                                                                     │
│  日志样本（learn 30%）                                                               │
│    ↓ SpanAwareTokenizer（E2，前缀 17 span/256 char）                                │
│    ↓ M3 结构学习（E0 重建 + E2 修复）：4-span 族签名分组 → 组内递归扫描             │
│      → family/value/kind 三类分裂决策树（E2-D）                                      │
│    ↓ 边界候选 = span 下标 → 字符偏移（E2-C 精化：last_close_end 尾缀词字符）         │
│                                                                                     │
│  验证样本（val 20%）                                                                 │
│    ↓ E3-B 可靠性统计：规则键 = (签名, 4 维边界结构组合)                              │
│      → {支持数, 接受准确率, over 率, 边界稳定性, 可靠性}                             │
│    ↓ 工作点选择：τ_B（val over ≤0.5% 下最大化覆盖）                                 │
│                                                                                     │
│  E4-A 编译器 compile_ruleset(τ)                                                      │
│    → 来源索引 → 签名索引 → 序列化决策树 + 扁平条件规则 + 门控放行位                  │
│    → header-rules/v1 JSON（151 KB/τ；树相同仅放行位不同）                            │
│                                                                                     │
└─────────────────────────────────────────────────────────────────────────────────────┘
                                        ↓ 规则文件（版本化，禁止在线修改）
┌───────────────────────────── 在线（每行日志） ──────────────────────────────────────┐
│                                                                                     │
│  match(raw_log, source)                                                             │
│    1. 来源索引命中？（未知来源 → KEEP，0.16 µs）                                     │
│    2. 惰性解析前 4 个 span → 签名索引命中？（未知签名 → KEEP，≈2 µs）                │
│    3. 树游走（family/value/kind 等值匹配，按树深度补解析，need p90=4）                │
│       → 叶 = span 边界 b；未命中 fallback → KEEP                                     │
│    4. 边界结构组合 → 门控表放行位（无 val 证据 / rel < τ → KEEP）                    │
│    5. ACCEPT：body_start = spans[b].start（或 last_close_end 精化）                  │
│       → return raw_log[body_start:]                                                 │
│                                                                                     │
│  P3 融合运行时实测：5.1–6.1 µs/行（P0 完整路径的 10–12×），p99 ≤16.7 µs              │
│  在线无统计计算、无边界搜索、无跨行状态（classify 记忆化为有界纯函数缓存）            │
│                                                                                     │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

## 组件与版本对应

| 组件 | 实现 | 引入实验 | 验证 |
|---|---|---|---|
| Span 分词（含空格括号字段/相邻分裂/未闭合回退） | `spantok.py` | E2 | 挑战集 cat1–cat5 |
| M3 决策树（签名分组+递归分裂+双守卫） | `methods.py`（E0 重建，E2 修复 by_value/未闭合安全） | E0/E2 | E0 消融 + E2 偏移声明 |
| 内容括号守卫 / 内型分裂 / 字符精化 | `span_methods.py` | E2 | Messages 0→0.926 等 |
| (签名,组合) 可靠性门控 | `gating.py` | E3 | 拦截 89.6%，内容级 over 0.21% |
| 规则编译器 / 匹配器 | `e4_compiler.py` / `e4_matcher.py` | E4 | 18,798 行双 τ 逐行等价 |

## 安全边界（E4-E 验证）

未知来源 / 未知签名 / 无验证证据组合 / 低可靠性 → 全部 KEEP（零违例）。
**来源名是安全边界的一部分**：跨源误路由时精确结构碰撞可发生剥离
（E4 §6），生产要求来源标识可信。【推断】生产来源元数据来自采集器，
可信度需在 E5 集成时确认。

## 与 PIPLUP 的关系

本阶段（E0–E4）**未修改 PIPLUP 核心代码**（五个实验分支仅改动
`bench/` 与 `docs/rep/header-detector-v11/`，已程序化核验）。
HeaderDetector 作为独立组件产出 `body_start` 偏移；PIPLUP 集成方式
（替换 format_chaos 清洗路径）与端到端开销属 E5 范畴，未验证。
