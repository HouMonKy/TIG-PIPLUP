# 算法机制：E1 / E2 / E3 / E4

各算法的精确实现以对应分支代码与报告为准；本文为机制摘要与证据链。

---

## 1. M1–M4（E0 重建基线）

- **M1** 位置变化率：边界 = 第一个变化率 >0.5 的位置。时间戳在
  0/1 位即变化 → 不可用（acc 0–6%）。
- **M2** 位置变化率+字段类型：全局扁平扫描；位置恒定（≥90%）或
  类型一致（≥90%）且 headerish 则消费。单一标准格式强（Loghub
  50.3%），混合流崩溃（压力集 6%）。
- **M3** = M2 + 4-span 族签名分组 + 组内递归扫描：
  - 恒定 → 前进；类型一致且 headerish → 前进；
  - 类型一致但弱（WORD/OTHER）→ 正文（未闭合括号内按值分裂续扫）；
  - 类型混杂 → 分裂：强类型族按 (族,值) 分裂续扫，弱类型停；
  - Guard A：前缀须含强类型证据，否则保留；Guard B：边界吞掉行
    75% token 时回退。
- **M4** = M3 + 值样正文首词回退 1 token —— 双向皆错，弃用
  （历史与重建结论一致）。

**E2 期间发现并修复的两处 M3 缺陷**（影响所有后续实验）：
1. `by_value` 遍历缺陷：值分裂节点构造未传标志，预测遍历永远 miss
   → 全部保守保留。修复后空白 M3 all22 0.663→0.733（E0 原协议）。
2. 未闭合括号安全：永不闭合的 `[` 不再被消费为头部字段。

## 2. E1：M2/M3 自适应规则学习

- 规则键 **(source, 4-token 签名)**；M2 规则 = 族内扁平边界，
  M3 规则 = 族内 M3 模态边界（按源拟合）。
- E1-A 选择准则：over-strip 风险优先（差距 >2pp 采纳更低者）→
  val 精度 → 更简单的 M2；双双不可靠 → KEEP。
- **关键教训（合并学习失败）**：Linux/OpenSSH 共享 syslog 签名，
  混流学习互相污染 → 必须按来源分组（E1-B 设计动机）。
- 结果：E1-A 以 −1.1pp 精度换 over 56×↓（0.034→0.0006），
  Loghub 反超原始 M3。

## 3. E2：Span-aware 分词与字符级边界

- **SpanAwareTokenizer**：括号深度 0 的最长非空白运行；
  含空格括号字段整体保留；仅"跨度以纯括号组开头且闭合后紧跟开括号"
  分裂（`[t][i][l]`）；前缀附着不分裂（`sshd(pam_unix)[19939]:` 单跨度）；
  不平衡回退纯空白分词；不变量 `raw[start:end]==text`。
- **内容括号守卫**（括号包裹≠头部）：内型自由文本（≥2 词、≥60%
  纯词、无时间模式）且多样性 >0.5 → 正文。
- **内型分裂**：同签名下 content/structural 混合时按内型分裂，
  structural 侧须前瞻 3 位内有后续括号结构才续扫
  （`[user5639] opened` 停、`[t][i][i][l][content]` 续）。
- **字符级精化**：边界跨度含已闭合括号组且尾随词字符
  （`[svc]disk`）→ `body_start = last_close_end`。
- 消融：E2-B（仅分词）已把挑战集 over 0.304→0.051；E2-C 守卫/精化
  把压力集 0.589→0.644、Messages 0→0.926；E2-D 前缀限定（17/256）
  与完整分析等价，采纳。

## 4. E3：置信度门控（不修改边界，只决定 ACCEPT/KEEP）

- **规则键 = (4-span 签名, 4 维边界结构组合)**：
  `value_end`（最后消费 span 值样：ID/NUM/HEX/HOST/IP/HOST_PORT/
  DOTTED/NUM_EPOCH，val over 14.1%）、`plain_ctail_end`（裸 `word:`
  无数字无括号）、`value_start`（正文首 span 值样）、`weak_end`
  （最后消费 span 纯词样，深过剥签名）。
- **可靠性** = val 接受准确率 × min(1,n/10) × 边界稳定性 ×
  max(0,1−4×over)；放行条件 n≥2 且 rel≥τ_B；无 val 证据 → KEEP。
- **核心发现**：同族内正确路径与误删路径常落在不同组合
  （OpenStack 正确行 value_start=True vs 误删行全 False）——
  组合并入规则键后可只杀误删路径。
- **负面结果**：E3-C 独立全局风险层在组合键控 B 之上零增量
  （D≡B）；单独拦截率仅 34%。其信号价值已被规则键吸收。
- 工作点：τ_B=0.4（over 0.45%/内容级 0.21%/覆盖 0.714）或
  τ_B=0.2（over 0.91%/覆盖 0.771），val 选定。

## 5. E4：离线编译 + 在线匹配

- **编译器**：E2-D learn 拟合树 + E3-B val 门控表 + 固定 τ →
  来源索引→签名索引→序列化树（family/value/kind 分裂+fallback）
  + 根叶路径扁平条件序列 + 门控放行位。规则不含固定字符偏移
  （边界由 span 动态解析吸收字段长度变化）。
- **匹配器四级**：P0 原始完整路径（51–116 µs）→ P1 扁平顺序匹配 →
  P2 索引树游走（≈18 µs）→ P3 融合单遍（**5.1–6.1 µs**，10–12×）。
- **P3 等价保持优化**（每步重跑 18,798 行等价验证）：正则跳读扫描器
  （与原扫描器 20,014 对抗样本逐位一致）、末开括号分界、按树深度
  惰性解析（need p90=4）、有界 classify 记忆化（64K 纯函数缓存）、
  空 span 边界行为精确复刻。
- **等价性**：P1/P2/P3 在 18,798 测试行 × τ∈{0.4,0.2} 上与 E3-B
  逐行完全一致（action/offset/正文/规则来源四维）；P0 复算汇总与
  已提交 E3-B 结果逐位一致。
- **安全**：未知来源 0.16 µs 全 KEEP；LODO 23 源 0 违例；
  无模糊匹配（条件全为精确等值判断）。
