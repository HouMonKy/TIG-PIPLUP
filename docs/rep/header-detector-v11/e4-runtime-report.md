## 0. 结论摘要

1. **规则化等价达成**：E3-B 的完整检测路径可完整编译为离线规则集 +
   在线匹配器。P1/P2/P3 三种运行时在全部 **18,798 测试行**上与 E3-B
   原始路径**逐行完全一致**（ACCEPT/KEEP、body_start_offset、剥离后
   正文、规则来源四维全同），τ=0.4 与 τ=0.2 双阈值均验证；P0 复算的
   汇总指标与已提交 E3-B 结果**逐位一致**（acc 0.7183 / over 0.0045 /
   cov 0.7143）。
2. **性能目标达成**：P3（融合运行时）平均在线处理 **5.1–6.1 µs/行**
   （8 场景），为 E3-B 完整路径（P0，51–116 µs）的 **10–12×**；
   初步目标 ≤5 µs 在 5/8 场景达成（bracket 5.14、low_hit 5.47、
   repeated 5.36、high_hit 5.96、many_distinct 5.82），混合格式
   6.08、长行 8.73。未知来源快速拒绝 **0.16 µs**。
3. **零模型零统计在线化**：在线路径不运行 M2/M3 统计、不运行 E2-D
   边界搜索、不重算跨日志置信度——全部决策来自编译期固化的
   (source, signature, boundary_structure) 规则。
4. **安全回退全部保持**：未知来源 0/18798 违例；LODO 23 个留出源
   0 违例；已知签名但无验证证据的组合 8 行全部 KEEP；跨源误路由的
   残余剥离为**精确结构碰撞**（非模糊匹配），集中出现在边界漂移的
   stress 变体目标上（§6）。
5. **建议进入 E5**（条件与注意项见 §8）。

## 1. 离线编译器设计（E4-A）

`bench/header_detector/e4_compiler.py` · `HeaderRuleCompiler`
（入口 `compile_ruleset(tau, ...)`）。

**输入**（与 E3 实验完全一致的数据流，无任何重选）：
- E1 的来源及结构分组——来源 = 数据集身份，结构分组 = 4-span
  类型签名（E1 自适应选择经 E3 验证为保守等价，全源统一 E2-D）；
- E2-D 拟合产物——learn 切分（30%，种子 42）拟合的
  `SpanM3Prefix` 决策树（`group_trees`）；
- E3-B 组合键可靠性表——val 切分（20%）上 `build_rules` 的
  (签名, 边界组合) → {支持数, 接受准确率, over 率, 稳定性, 可靠性}；
- 验证集选定的门控阈值——τ_B ∈ {0.4, 0.2}（E3 报告的两个工作点，
  规则学习固定，**未根据测试集结果重选或修改**）。

**输出**（版本化规则集 `header-rules/v1`，JSON）：
- **来源索引**：source → {树索引, 门控表, 扁平规则表, 元数据}；
- **树索引**：4-span 签名 → 序列化决策树（`family`/`value`/`kind`
  三类分裂、per-family fallback、SHORT 短路——与
  `M3Detector.predict_token_boundary` 的游走语义逐位对应）；
- **前缀匹配条件**：每条根→叶路径展开为有序条件序列
  （`len_le`/`value`/`kind`/`fam`/`strong`/`not_value`/`not_kind`/
  `fam_not_child`/`fam_other`），供 P1 顺序匹配；
- **动态正文边界计算方式**：叶的 span 下标 b → 字符偏移
  （`spans[b].start` / 行尾 rstrip）+ E2-C 字符级精化
  （`last_close_end` 尾缀词字符）——**编译规则不含任何固定字符
  偏移**，时间戳/模块名/线程字段长度变化由 span 动态解析吸收；
- **拒绝条件**：未知来源 / 未知签名 / 树游走未命中 fallback→0 /
  门控无验证证据 / 可靠性 < τ，全部输出 KEEP；
- **规则支持度与可靠性元数据**：每条门控条目携带 n / val_acc /
  val_over / stability / reliability / modal_boundary。

**(source, signature, boundary_structure) 区分能力**：来源索引 →
签名索引 → (签名, 组合) 门控表三级键控，OpenStack 同族正确路径
（value_start=True 组合）与误删路径（全 False 组合）在门控表中是
不同条目，编译后不会被重新合并。

**编译产物规模**（每 τ 一套，树相同仅门控放行位不同）：

| τ | 树 | 扁平规则 | 门控条目 | 放行 | 编译耗时* |
|---|---:|---:|---:|---:|---:|
| 0.4 | 215 | 659 | 96 | 58 | 1.60 s |
| 0.2 | 215 | 659 | 96 | 72 | 1.63 s |

\* 含 E2-D 拟合 1.14 s + val 统计 0.48 s（23 源合计，纯离线）。
规则文件 151.4 KB/套。

**树深度预算验证（17/256 合理性）**：逐树 `need`（树可查询的最大
span 下标 +1）p90 ≈ 4，各源最大 ≤ 11——17-span / 256-char 预算比
任何学习树的实际查询深度富余 1.5–4×；256-char 上限仅在长行场景
生效且无病态尾延迟（§4）。P3 已按树深度惰性解析（§2）。

## 2. 在线匹配器设计（E4-B）

`bench/header_detector/e4_matcher.py` · 统一接口：

```python
match(raw_log: str, source: str) -> {
    "action": "ACCEPT | KEEP",
    "body_start_offset": 0,
    "rule_id": None,       # ACCEPT 时为 source#签名#组合
    "reason": None,        # KEEP 时给出拒绝原因
}
```

四级运行时（同一规则集、同一输入对比）：

| 运行时 | 路径 |
|---|---|
| P0 | E3-B 原始完整检测（拟合检测器 predict + 门控，含 E3-B 固有的重复分词/重复预测） |
| P1 | 预编译扁平规则，顺序候选匹配（签名是每条规则匹配条件的一部分，根叶树靠它约束） |
| P2 | 来源索引 + 签名索引 → 编译树游走（元组节点） |
| P3 | P2 + 快速拒绝 + 有界前缀解析（全部融合为单遍） |

**P3 的等价保持优化**（正确性优先，全部可证等价）：
1. **正则跳读扫描器**（`_scan_hop`）：逐字符 Python 循环改为
   C 级正则跳到下一个"有趣字符"（空白/括号），普通字符段整段跳过；
   与 `SpanAwareTokenizer._scan_span` 在 20,014 个对抗样本（含 2 万
   随机括号串、嵌套/未闭合/256 截断）× 多起点上输出逐位一致；
2. **末开括号分界**：最后一个开括号之后的 span 不可能进入括号深度，
   纯 `\S+` 正则扫描；之前的 span 走精确扫描器；
3. **按树深度惰性解析**：先只解析 4 个签名 span（未知签名即刻
   KEEP，不扫余下前缀）；命中树后按该树的 `need` 补解析（p90 无需
   补）——解析工作量由规则深度而非 17 上限决定；
4. **跨行有界 classify 记忆化**（64K 条上限，纯函数缓存，非学习
   状态）：`type_family(classify(text))` 0.90 µs → 命中 0.02 µs；
5. **原分词器空 span 边界行为精确复刻**：扫描在 256 上限处卡住且
   后方仍有非空白时，原实现会向 17 上限填充空 span（其 .start 会
   进入边界计算）——P3 按需复刻到 `need`（树查询不超 need−1，
   已证等价）；37,593 数据行 × 3 种 need 逐 span 验证一致。

**在线路径排除项**（合规自查）：无 PositionStats/分裂学习（M2/M3）、
无边界搜索（树游走是编译规则的匹配，不是学习）、无跨日志置信度
计算（门控放行位编译期固化）、不遍历全部规则（P2/P3 两次字典命中；
P1 顺序扫描为对照设计）、常规前缀检测不扫描整条日志（≤256 字符 +
惰性深度）。

## 3. E3-B 与 E4 逐行等价性（E4-C）

**方法**：P0 = E3-B 原始路径复算（与 `e3_runner.apply_gate` 在
τ_B、tau_c=off 下的在线代码逐句相同）；固定测试集 = 全部 23 源
test 切分（30/20/50，种子 42，与 E2/E3 完全一致）；逐行比较
ACCEPT/KEEP、body_start_offset、剥离后正文（偏移等价蕴含）、
规则来源（rule_id 的 source#签名#组合 部分）。

| τ | 运行时 | 一致 | action 差 | offset 差 | 新增正文误删 |
|---|---|---|---|---|---|
| 0.4 | P1 | 18798/18798 | 0 | 0 | 0 |
| 0.4 | P2 | 18798/18798 | 0 | 0 | 0 |
| 0.4 | **P3** | **18798/18798** | **0** | **0** | **0** |
| 0.2 | P1/P2/P3 | 18798/18798 各 | 0 | 0 | 0 |

**与已提交 E3 结果对账**：P0(τ=0.4) pooled 与 `e3_results.json`
的 E3-B 汇总**逐位一致**（n=18798，acc 0.7183 / over 0.0045 /
cov 0.7143 / accepted 0.9791 / bodyInt 0.9991）；
P0(τ=0.2) 与 E3 测试曲线 τ_B=0.2 行一致（over 0.0091 /
cov 0.7707≈0.771）。注：E3 报告正文"19,700 行"为笔误，提交数据
的 n 即 18,798。

**失配归因**（开发过程发现并修复的实现缺陷，最终为零）：
1. 根叶树（无分裂条件）的扁平规则会匹配任意行——P1 增加签名约束
   后修复（1442+678 → 0）；
2. `not_key` 条件未区分 value/kind 分裂的运行时键——拆分为
   `not_value`/`not_kind`；
3. 强类型族缺 fallback 时漏发 0 规则（树返回 0、扁平规则集无覆盖
   → rule_no_match）——补 `fam_not_child(fallback.get(fam, 0))`。
   规则表达能力不足：**0**（E2-D 树可完整序列化）；为性能主动放弃
   的覆盖：**0**（P3 全部优化可证等价）；新的正文误删：**0**。

## 6. 未知格式与安全回退（E4-E）

| 检查 | 结果 |
|---|---|
| 未知来源 → KEEP | **0 违例** / 18,798 行（offset 全 0） |
| LODO（留出源不在索引，23 源逐一） | **0 违例**（来源索引天然隔离；无签名级跨源迁移——E4 规则按源编译，不存在 E3 LODO 实验中的全局风险表） |
| 已知签名、无 val 证据的组合 → KEEP | 8 行全部 KEEP（`gate_b(None)=False` 编译期固化） |
| 门控低可靠性拒绝 | 3,190 行（验证过但 rel < τ） |
| 模糊规则扩大剥离 | **不存在模糊匹配**——规则条件是精确的值/类型/类别等值判断 |

**跨源误路由**（调用方给错来源名的误配场景，非规则缺陷）：
23×22 方向全量路由，11866 accept / 401690 keep / 1491 over-strip。
结构性同源格式（Linux/OpenSSH/Thunderbird 系 loghub 同构）误路由后
**0 误删**——精确结构碰撞剥离点也一致；over 集中在边界漂移的
stress 变体目标：challenge 136、stress-deploy 577、
**stress-dsware 570**（1707 accept）。dsware 专项（E1 跨源误删
问题的延续）：误路由进 dsware 的外部行 2.9% 被接受、其中 570 行
over——这些是"与 dsware 学习变体结构完全相同但边界不同"的行；
**正确来源路由下（正常工作方式）dsware 自身 over=0（E3-B 已门控）**
。结论：来源名是安全边界的一部分，误配 + 精确结构碰撞可剥离，
无法在不放弃结构匹配的前提下消除——生产要求来源标识可信。

## 8. 是否建议进入 E5

| 判据 | 结果 |
|---|---|
| 正确性 | 18,798 行双阈值逐行等价，零新增误删 ✓ |

4. 17/256 前缀预算经树深度验证为富余（need p90=4），P3 已按需
   解析，无需收紧。

**本阶段未修改 PIPLUP 核心代码，未合并任何稳定分支**（全部改动
位于 `bench/header_detector/e4_*.py`、`bench/header_e4.py` 与
`docs/rep/header-detector-v11/`）。
