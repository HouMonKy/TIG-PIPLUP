# E3：置信度门控与正文保护实验报告

**项目：** TIG-2026 / PIPLUP HeaderDetector V1.1  
**分支：** `exp/header-v11-gate`（自 E2 提交 `811914c6` 创建）  
**日期：** 2026-10-22

## 0. 结论摘要

1. **门控目标达成**：E3-B（规则可靠性门控）在测试集上将 Over-strip 从
   **4.29% 降到 0.45%**（内容级误删 4.01% → **0.21%**，即 807 行误删
   拦截 723 行），Auto-strip Coverage 保持 0.714（为无门控的 81%），
   Accepted Boundary Accuracy 0.897 → **0.979**，字符级 Body Integrity
   0.982 → **0.999**。**探索目标 Over-strip ≤0.5% 在不牺牲剥离主体
   能力的前提下达成**（保留 88% 的原始正确剥离：损失率 11.75%）。
2. **核心设计发现**：可靠性规则必须以 **(签名, 边界结构组合)** 为键，
   而非单独的签名族。OpenStack 同族内正确行（边界落在客户端 IP，
   value_start=True）与误删行（吞掉 `[instance: uuid]` 正文括号，
   全 False 组合）落在**不同组合**中——组合维度并入规则键后，
   门控可以只杀误删路径而保留正确路径。
3. **E3-C（独立正文风险层）无增量收益**：其全局组合风险表在组合键控
   的 E3-B 之上拦截率 0 增（E3-D ≡ E3-B）；单独使用时拦截率仅 34%。
   **负面结果，如实报告**：正文风险信号的价值已被吸收进规则键，
   不建议作为独立层进入 E5。
4. 前置一致性检查确认：E3-A 与 E2-D **逐数据集逐位一致**；修复版 M3
   下重跑 E1，E1-A/B/C 结果**逐位不变**（自适应选择的保守性对基线
   修复免疫），M3-RULE/M3-raw 参照提升约 7pp（附表）。
5. LODO 跨源迁移（独立实验）：无门控迁移宏平均 over 4.21%，C 门控
   可压至 0.80% 但覆盖率同时崩塌（全局组合表过于鲁莽）——维持
   **未知来源默认 KEEP** 的结论。
6. **建议 E3-B 进入 E5**（工作点 τ_B=0.4；覆盖优先替代点 τ_B=0.2：
   over 0.91% / 覆盖 0.771）。

## 2. 方法实现

### 2.1 总体约束

门控**只产生 ACCEPT（沿用 E2-D 边界）或 KEEP（保留原文）**，不修改
任何边界位置；E2-D 自身的弃权（pred=0）不受门控影响。由此门控贡献
可单独归因（消融见 §4）。

### 2.2 E3-B：规则可靠性门控（gating.py `build_rules`）

- **规则键 = (4-span 签名, 边界结构组合)**。结构组合为 4 个布尔特征：
  - `value_end`：最后消费的 span 是值样类型（ID/NUM/HEX/HOST/IP/
    IP_PORT/HOST_PORT/DOTTED/NUM_EPOCH）——"值样正文首词被吞"的签名；
  - `plain_ctail_end`：最后消费 span 是无数字无括号的裸 `word:`
    （组件式 `sshd[19939]:` 有锚定，不算）；
  - `value_start`：正文首 span 是值样类型；
  - `weak_end`：最后消费 span 是纯词样内容（WORD/OTHER/FCALL）——
    深过剥签名（如吞掉常量 IP 后停在 `"GET`）。
- **离线统计（仅 val）**：每条规则的剥离支持数、验证集接受准确率、
  over 率、边界稳定性（模态边界占比）。
- **可靠性**：`rel = accB × min(1, n/10) × stability × max(0, 1−4×over)`
  （沿用 E1-C 形式）。放行条件：`n ≥ 2 且 rel ≥ τ_B`；无 val 证据的
  规则（测试出现新组合）→ KEEP（保守）。
- **在线成本**：一次 (签名,组合) 字典查找，无任何统计重算。

### 2.3 E3-C：正文风险门控（`BodyRiskModel`）

在 **pooled val 剥离行**上学习 (4 布尔特征) 组合 → over 率的先验表；
线上组合的 val over 率 > τ_C（支持 ≥5）则 KEEP。不含任何数据集名、
具体单词、IP 或主机模式——信号全部来自候选边界两侧的结构类型。

### 2.4 E3-D：联合门控

E3-B **与** E3-C 同时放行才 ACCEPT。

### 2.5 工作点选择（仅用 val）

目标：val over ≤ 0.5% 下最大化 val 覆盖率。选中：
**E3-B τ_B=0.4；E3-C τ_C=0.05；E3-D (0.4, 0.15)**。

## 3. 风险表（pooled val，E3-C 先验）

| 组合 (value_end, plain_ctail_end, value_start, weak_end) | n | val over |
|---|---:|---:|
| (True, F, F, F) | 725 | **14.1%** |
| (F, F, F, True) | 57 | 7.0% |
| (F, **True**, F, F) | 1109 | 1.1% |
| (F, F, F, F) | 4327 | 4.8% |
| (F, F, **True**, F) | 374 | 0.3% |
| (F, T, T, F) | 44 | 0.0% |

值样结尾边界是最高风险信号（14.1%），正文首 span 值样反而低风险
（0.3%——那是正确边界落在 IP/ID 前的形态，如 OpenStack 正确行）。
全 False 的兜底组合含 4.8% over（族级病灶混杂），全局先验无法
安全拦截——这正是 E3-C 单独失效、必须依赖规则键细化的原因。

## 5. LODO 跨源迁移（独立实验，与已知来源门控分开统计）

按指令：未知来源默认 KEEP。单独探索的签名迁移（E2-D 拟合于其他
来源 learn，仅 E3-C 结构风险门控，风险表来自其他来源 val）：

- 宏平均 over：无门控 4.21% → C 门控 **0.80%**；但覆盖率同时大幅
  下降（如 Linux 0.967→0.042：全局兜底组合表把 (F,F,F,F) 一刀切）。
- 结论：跨源迁移**可以做到安全（over↓），但现有全局风险表过于鲁莽**；
  生产建议维持 E1/E2 结论——**未知来源默认 KEEP**，迁移仅允许
  高置信 per-source 规则（E4 范畴）。

## 6. 在线开销

- 门控增量：**5.35 µs/行**（predict 23.9µs → 29.3µs，+22%）。
  构成：边界特征提取（重复调用 predict_token_boundary + span 扫描）
  + 两次字典查找。E4 编译规则时特征可与检测器单遍融合
  （边界 span 已在手），预计增量 <1µs；当前值是保守上界。
- 规则规模：23 数据集共 ~190 条 (签名,组合) 规则，加载为纯字典，
  无在线统计计算（合规：不在线重跑 M2/M3）。

## 8. 拦截成功与失败案例

**成功**（over→KEEP）：
- `[t][lvl][proc] vm-61e8 reported...`（host-body）：值样结尾组合，
  规则 val over ~50% → KEEP ✓
- `... [req-...] [instance: fecdd5a9-...] VM Resumed`（OpenStack
  误删路径）：全 False 组合规则 val over 高 → KEEP（同族正确路径
  value_start=True 组合保留）✓
- `... [INFO] backpressure: inbound queue...`：裸 CTAIL 结尾 → 风险 ✓

**失败**（over 仍放行）：
- 挑战集 39 行空白怪癖（内容零损失，见 §4 注）；
- Mac 26 行 `-[ObjC selector]` 深过剥：与其正确剥离同组合、同族
  （val 混合 12% over），τ_B=0.4 下规则仍被放行——残余内容误删
  的主要来源；
- BGL 7 行 `idop` 值样正文：规则 val over ~0.7%，低于任何合理阈值。

## 9. 是否建议进入 E5

| 组件 | 判断 | 理由 |
|---|---|---|
| **E3-B（(签名,组合) 规则可靠性门控）** | **建议进入 E5** | over 4.29%→0.45%（内容级 0.21%），拦截 89.6%，覆盖率保留 81%，accepted 0.979，在线成本一次字典查找 |
| E3-C（独立正文风险层） | **不建议** | 在 B 之上零增量（D≡B）；单独拦截率仅 34%；其信号已被 B 的组合键吸收。负面结果如实报告 |
| E3-D | 不作为独立组件 | 等价于 E3-B |
| LODO 迁移 | 维持默认 KEEP | 迁移+全局风险表覆盖率崩塌；如需迁移须 per-source 高置信规则（E4） |

**E5 集成注意**：(1) 工作点按业务风险偏好二选一：τ_B=0.4
（over 0.45%/覆盖 0.714）或 τ_B=0.2（over 0.91%/覆盖 0.771），
两点的完整曲线已交付；(2) 门控规则 (签名,组合)→ACCEPT/KEEP 天然
编译为 E4 规则文件的一个布尔字段；(3) 挑战集空白怪癖属 GT 侧问题，
E5 前可修正生成器前导空格（影响 39 行统计，不影响方法结论）。
