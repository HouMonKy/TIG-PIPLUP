**架构演进**：人工 format_chaos 配置 →（E1）per-source 规则原型 →
（E2）字符级 span 边界 →（E3）(签名,组合) 可靠性门控 →
（E4）全部编译为"来源索引→签名索引→决策树→门控位"的确定性规则，
在线零统计、零模型。

## 2. 各阶段核心改进（证据见各报告）

- **E0**：可复现协议（种子 42 / 严格隔离 / 字符级四分类）；
  7 类错误样本库（C1–C7）成为后续实验的靶点。
- **E1**：规则键 (source, signature)；over 优先的选择准则；
  "双双不可靠→KEEP" 保守路径；LODO 揭示跨源迁移风险。
- **E2**：SpanAwareTokenizer（不变量 `raw[start:end]==text`）；
  最小相邻括号分裂；内容括号守卫（括号包裹≠头部）；内型分裂+
  前瞻约束；`last_close_end` 字符级精化（`raw[offset:]` 直接切片）。
- **E3**：4 维边界结构组合（value_end/plain_ctail_end/value_start/
  weak_end）并入规则键；val-only 工作点选择；content_over 与
  whitespace_over 分离；转移矩阵/拦截率/损失率评估框架。
- **E4**：序列化决策树（family/value/kind 分裂）+ 扁平条件规则 +
  门控放行位；P3 五项等价保持优化（正则跳读扫描器 20,014 对抗
  样本验证、末开括号分界、按树深度惰性解析、有界 classify 记忆化、
  空 span 行为复刻）。

## 5. 已证明无效的探索（保留失败结论，不进 E5）

1. **M4 正文证据回退**（E0）：值样正文首词触发回退 1 token，
   双向皆错（host-body 0.426→0.129）。
2. **合并学习/全局签名规则**（E1）：跨源签名污染。
3. **8-token 长签名**（历史结论 + E0 过程验证）：正文特征污染分组。
4. **E3-C 独立全局正文风险层**（E3）：组合键控 B 之上零增量
   （D≡B）；单独拦截率仅 34%——信号已被规则键吸收。
5. **LODO 宽松签名迁移 / 全局风险表迁移**（E1/E3）：可压 over 但
   覆盖崩塌（Linux 0.967→0.042）——未知来源维持默认 KEEP。
6. **P1 顺序规则扫描作为运行时**（E4）：随规则数线性退化
   （114 条 31.2 µs）——被 P2/P3 索引化取代。

## 6. 当前最佳候选方案及其限制

**方案**：E4-P3 运行时 + `rules_tau0.4.json`（或 τ0.2）。

- 质量边界：acc 0.718 / over 0.45%（内容级 0.21%）/ 覆盖 0.714 /
  accepted 0.979（23 数据集宏平均 acc 0.693，挑战集 0.868）。
- 性能边界：5.1–6.1 µs/行、p99 ≤16.7 µs、未知来源 0.16 µs、
  规则 151 KB/τ、索引 3.4 MB、来源数扩展平坦。
- **限制**（详见 design/limitations.md）：
  1. 覆盖率代价 17pp，正确剥离损失 11.75%（93% 集中在 4 个
     val 高危族；τ=0.2 或 per-source τ 可换）；
  2. 残余内容误删 41 行/18,798（Mac 深过剥、BGL idop、
     结构上局部不可分）；
  3. 来源名是安全边界：误配来源+精确结构碰撞可剥离
     （dsware 误路由 570 行 over；正确路由下 0）；
  4. 验证域限 23 源合成+公开数据、单行日志、单线程 Python；
     生产规模、多行日志、非拉丁字符、PIPLUP 端到端均未验证；
  5. 无分隔符格式（HealthApp 管道）与异构节点字段（HPC）为
     各方法一致的长期未解。

## 7. E5 待验证事项

1. **PIPLUP 端到端集成**：以 `match(raw_log, source)` 替换
   format_chaos 清洗路径；验证端到端额外开销 <5% 目标
   （本阶段仅证检测器自身 5–6 µs）。
2. **来源标识可信性**：生产采集器元数据的准确率与降级策略
   （来源错误时安全边界失效，§6.3）。
3. **E1 方法选择在 span 签名上重建**：E4 采用"全源统一 E2-D"
   的保守等价；E1 式 per-source M2/M3 选择重建后是否有增量
   （E1 证据：M3 仅在少数括号族必要）。
4. **E5 消融**：组合收益分解（E2 分词 / E3 门控 / E4 编译各自
   贡献），以及双 τ 工作点在真实业务分布下的选择。
5. **规则治理**：格式漂移检测与重拟合→重编译节奏；
   规则文件版本化审计（E4 `_compile_meta` 计时字段建议移出）。
6. **遗留小项**：挑战集 GT 前导空格修正（39 行统计）；
   Mac/BGL 残余误删是否需要更细规则键（未实验）。
